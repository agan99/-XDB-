## 2. 旧稿不能直接沿用的内容

1. **文件路线未定**：旧稿把 `媒体库.xdb`、新总库插件和多个数据库字段当成既定实现；当前目录没有这些实现，必须重新确认原生 `.xdb` 与 `*.xdb.js` 的职责。
2. **需求和方案混写**：旧稿同时冻结导航、字段解析、卡片 DOM、CSS 前缀、插件注册方式、批量加载和测试数量，导致后续任何一处变化都需要整份计划重写。
3. **类型边界过早固定**：动画和游戏已有真实字段；剧集、电影、书籍、漫画还没有各自的正式属性与卡片 Requirement，不能在 Task 09 中替它们决定日期、状态措辞或额外字段。
4. **排序规则不一致**：旧稿出现过“日期”以及三种主动排序的不同版本；当前顶部导航只确定 `[个人评分][完成日期]`，排序方向、默认顺序和空值规则要在新 Task 中一次确认。
5. **状态层级容易越界**：笔记保存中性状态；动画/游戏卡片已有类型显示映射。集合画廊的筛选用词、未来媒体的卡片用词不能从旧 Reference 自动推导。
6. **卡片边界容易膨胀**：旧稿虽然排除了进度，但仍混入旧卡片的字段、日期回落、角标和通用卡实现细节。集合卡片必须以两份集合规范的结构图和信息流表为边界。
7. **Reference 被误当需求**：`Reference/参考-设计规范.md` 的简介、推荐语、产地、旧状态字段和旧类名只用于理解来源，不得直接带入集合卡片。
8. **验证目标需重建**：旧稿写死测试数量、旧文件哈希和不存在的目标文件名；新 Task 必须根据实际目标文件重新列 Agent Verification 与 Human Acceptance。

## 3. 重写时必须先确认

- 顶部导航固定顺序：

  ```text
  [★收藏] 🔍 搜索…… [全部][动画][游戏][剧集][电影][书籍][漫画]
  | [全部][待定][进行中][已完成][暂缓]
  | [个人评分][完成日期]
  ```

- 类型筛选是否多选、状态筛选是否单选，以及按钮数量是否显示；
- 六类媒体的入库边界和 `作品大类` 缺失值处理；
- 集合卡片公共字段与未来媒体专属字段的边界；
- `开播日期`、`发行日期`、`完成日期` 的使用范围；
- 卡片是否只读，以及任何写回是否另立 Requirement；
- 是否需要渐进加载、批次大小和真实容器验收方式；
- 新目标文件名、XDB schema、插件扩展点和测试文件。
