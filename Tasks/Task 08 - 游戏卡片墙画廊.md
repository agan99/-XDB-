## ⁠1. ⁠Goal

实现游戏媒体库的「游戏卡片墙」画廊。

画廊负责游戏集合的筛选、搜索、排序、卡片排列和渐进加载，并复用 Task 07 的游戏卡片。

## ⁠2. ⁠Requirement

### ⁠2.1 ⁠筛选

状态筛选为单选：

```text
全部
在玩
想玩
已玩
暂缓
```

状态标签与游戏笔记原始取值的映射（与 Task 07 卡片的四态 key 一致）：

| 笔记 `状态` 原始值 | 四态 key | 画廊标签 |
| --- | --- | --- |
| `▶️ 进行中` | `watching` | 在玩 |
| `⏳ 待定` | `planned` | 想玩 |
| `✅ 已完成` | `completed` | 已玩 |
| `💭 未来也许` | `paused` | 暂缓 |

规则：

* 点击状态只显示对应游戏；
* 再次点击当前状态恢复「全部」；
* 「全部」只清除状态筛选；
* `★ 收藏`、`时长未知` 为独立开关；
* 状态筛选和附加筛选之间使用 AND。

筛选按钮数量始终基于完整游戏库统计，不随当前筛选或搜索变化。

### ⁠2.2 ⁠搜索

搜索范围：

```text
中文名
原名
tags
```

规则：

* 包含匹配；
* 英文字母忽略大小写；
* 忽略输入首尾空格；
* 多关键词以空格分隔；
* 多关键词之间使用 AND；
* 每个关键词可匹配三个搜索字段中的任意一个。

### ⁠2.3 ⁠排序

默认排序：

```text
状态优先级
→ 发行日期倒序
→ 标题正序
```

状态优先级：

```text
在玩
→ 想玩
→ 暂缓
→ 已玩
```

提供三个可切换排序：

* 发行日期；
* 个人评分；
* 标题。

排序按钮采用：

```text
未选中
→ 默认方向
→ 反向
→ 恢复默认排序
```

同一时间只允许一个主动排序。

空值始终排在最后；主排序值相同时使用标题正序。

### ⁠2.4 ⁠卡片与布局

画廊必须复用 Task 07 的游戏卡片，不重新实现卡片内部展示。

布局：

* 规则网格，不使用瀑布流；
* 卡片等高；
* 根据可用宽度自动调整列数；
* 正常最小卡片宽度 `210px`，实际宽度由容器可用宽度与列数计算；
* 最后一行从左向右排列；
* 不产生横向滚动条；
* 极窄窗口无法容纳最小卡片时允许整体缩小。

### ⁠2.5 ⁠渐进加载

不使用传统分页。

处理顺序：

```text
游戏全集
→ 筛选
→ 搜索
→ 排序
→ 完整结果集
→ 分批渲染
```

第一版每批约 `24` 张。

接近结果底部时继续加载，直到当前完整结果集显示完毕。

筛选、搜索或排序发生变化时：

* 重新计算完整结果集；
* 重置已渲染批次；
* 从第一批重新显示；
* 回到卡片结果区域顶部。

卡片内部数据修改不默认导致整个画廊回到顶部；如果修改后不再满足当前筛选条件，只更新当前结果集并移除该卡片。

### ⁠2.6 ⁠空结果

筛选或搜索无结果时显示：

```text
没有找到匹配的游戏
调整搜索或筛选条件试试
[清除条件]
```

「清除条件」清除搜索、状态及附加筛选，但保留当前排序。

游戏库本身为空时显示：

```text
暂无游戏
当前游戏库没有可展示记录
```

画廊不提供新增游戏入口。

## ⁠3. ⁠Scope / Contract Boundary

本 Task 只负责画廊级能力：

* 集合筛选；
* 搜索；
* 排序；
* 筛选数量；
* 卡片网格；
* 渐进加载；
* 空结果状态。

数据集合继续使用现有游戏 XDB 数据边界（`作品大类 = 游戏 AND 数据来源 = Bangumi`）。

单张卡片必须复用 Task 07，不在画廊中复制卡片字段、状态映射、时长换算或任何写回逻辑。

画廊为只读：不提供状态切换、收藏切换、游玩时长编辑。

本 Task 不提前固定 `.xdb` / `*.xdb.js` 或具体 Gallery Renderer 技术方案，由 Plan Review 根据 Components/XDB 能力和对应 Skill 判断。

## ⁠5. ⁠Out of Scope

本 Task 不实现：

* 新的游戏卡片；
* 游戏数据新增或接入；
* 任何写回（状态切换、收藏切换、游玩时长编辑）；
* 动画侧改动；
* 旧 `game-gallery-wall.xdb.js` 的迁移、删除或改造；
* 虚拟列表。

## ⁠6. ⁠Acceptance Criteria

1. 状态、`★ 收藏`、`时长未知` 筛选符合正式组合规则。
2. 筛选数量始终基于完整游戏库。
3. 搜索范围和多关键词 AND 匹配行为符合 Requirement。
4. 默认排序（状态优先级 → 发行日期倒序 → 标题正序）及三种主动排序行为正确。
5. 空排序值始终排在最后，主排序相同时按标题正序。
6. 画廊复用 Task 07 游戏卡片，没有重复实现卡片逻辑。
7. 网格能根据可用宽度响应式调整列数，并且不产生横向滚动条。
8. 筛选、搜索和排序作用于完整数据后再进行渐进渲染。
9. 条件变化会重置渐进加载。
10. 两种空结果状态及「清除条件」行为正确。
11. 画廊为只读，没有引入任何写回调用。
12. 动画侧、`媒体库.xdb` 与旧游戏卡片墙脚本未受影响。

## ⁠7. ⁠Verification / Human Acceptance

Agent Verification：

* 验证筛选、搜索和排序逻辑；
* 验证完整结果集与渐进加载顺序；
* 验证筛选数量不受当前条件影响；
* 验证 Task 07 卡片被复用；
* 验证只读，没有引入写回；
* 验证动画侧测试未被破坏。

Human Acceptance：

* 在真实 Obsidian / Components 中检查画廊布局和响应式效果；
* 实际操作状态、收藏、时长未知筛选；
* 实际测试搜索和三种排序；
* 检查连续滚动加载及条件变化后的重置行为；
* 检查空结果与清除条件行为。
