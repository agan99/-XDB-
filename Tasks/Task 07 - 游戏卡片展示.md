## 1. Goal

实现基于现有游戏笔记标准属性的单张游戏卡片，并提供可在 Components/XDB 中检查真实游戏记录的入口。

## 2. Requirement

- 卡片按《媒体卡片设计规范》游戏卡片章节展示封面、游戏类型、状态、发行年月、个人评分、标题、收藏标记、tags、游玩平台和累计游玩时间。
- 字段使用游戏笔记现有的中文属性名；以 `300 Resources/310 媒体库/311 游戏 🎮/学习版/接线疑云_游戏.md` 为真实样例。
- `游玩分钟` 只表示累计时长。`150` 分钟显示为「2小时30分」；空值与非法值不冒充 `0`，有效的 `0` 显示为「0分钟」。
- 卡片不展示完成百分比、进度条、简介或简介入口；`✅ 已完成` 不推导为 `100%`。
- 缺失单个展示字段时保持卡片可用，不写入补造的源数据。
- 游戏卡片须能在只包含 `作品大类 = 游戏 AND 数据来源 = Bangumi` 的 XDB 数据范围内接受真实记录验收。
- 卡片视觉与结构对齐 `媒体库-动画卡片.xdb.js` 的动画卡片：同一套卡片几何（16px 圆角、封面 5:6 竖版完整显示、封面四角徽章体系）、同一套 12 组语义彩色标签、同一套四态状态标识色。
- 卡片宽度随容器自适应并有上限（330px），窄窗口下卡片等比收窄、封面不变形、不产生横向滚动。
- 视觉对齐只涉及展示层；动画卡片的可写操作（状态一键切换、收藏切换、集数增减）与进度区**不随视觉一起继承**。

## 3. Scope / Contract Boundary

- 本 Task 实现单张游戏卡片及其最小 XDB 验收入口；不实现游戏画廊级筛选、搜索、排序、网格或渐进加载。
- 游戏笔记 frontmatter 是展示数据的 Source of Truth。卡片不得使用旧游戏卡片墙的 `status`、`game_category`、`completion_percent` 作为标准属性，也不得创建第二套游玩时长或完成率字段。
- 当前只确定展示。状态切换、收藏写回、游玩分钟编辑等卡片操作不从动画卡片自动继承；如需加入，先补充正式 Requirement。
- **视觉对齐属于 Scope 内**：卡片几何、封面比例、四角徽章、标签配色与状态配色对齐动画卡片。这部分的实现代价是两个 `*.xdb.js` 各自持有一份同构的样式与配色表（插件模型不支持跨插件共享代码），两份副本的一致性由测试固定，不得各改各的。
- 保留现有动画 XDB、动画卡片及动画 Media Progress 的行为和数据边界。

## 6. Out of Scope

- 修改游戏笔记、采集流程或模板
- 按游玩分钟生成完成百分比
- 复刻动画的集数操作或简介功能
- 游戏画廊与其它媒体卡片

## 7. Acceptance Criteria

1. 《接线疑云》样例卡片显示「解谜」「已完成」「2024年07月」「★ 6.5」「接线疑云」及「学习版 · 已游玩 2小时30分」；空白 tag 被忽略。
2. 标题按 `中文名 → 原名 → name` 取第一个非空值；收藏标记与 `收藏` 的真实值一致。
3. tags 保持原顺序，最多显示前 5 个；缺失数据按正式规范降级。
4. `游玩分钟` 的空、非法、`0`、不足一小时和整小时等边界显示正确，不出现伪造的完成率。
5. XDB 验收入口能显示游戏记录，不混入动画；现有动画功能不受影响。
6. 卡片没有简介入口、进度条和未经批准的写回操作。
7. 卡片几何与动画卡片一致：圆角 16px；封面按 5:6 竖版完整显示（`object-fit: cover`，四张样例封面均不变形）；封面左上 `游戏类型`、右上 `状态`、左下 `发行年月`、右下 `★ 评分` 四个角标的位置与规格和动画卡片一致。
8. 标签走与动画卡片同源的 12 组语义彩色配色（如 `后宫/卖肉/肉` 同组），未命中关键词的标签由哈希落到同一套色板；无有效标签时整行隐藏。
9. 状态角标按四态使用与动画卡片相同的标识色：`未来也许` / `待定` / `进行中` / `已完成` 分别对应动画的 暂缓 / 想看 / 在看 / 已看 四色。
10. 卡片宽度随容器自适应、上限 330px；把窗口从宽拖到极窄，卡片等比收窄，不出现横向滚动条，封面不变形。
11. 卡片仍**没有**状态切换、收藏切换、集数操作、进度区和简介入口。

## 8. Verification / Human Acceptance

Agent Verification：验证字段映射、时间换算与缺失值、XDB 数据范围、插件语法与校验，并运行相关现有测试。

Human Acceptance：在真实 Obsidian / Components 中用《接线疑云》等游戏笔记检查卡片排版、封面、窄窗口、主题颜色与字段显示。

## 9. 接入约定

用户选择单独建立游戏卡片 `*.xdb.js`。该文件是插件，不承担 `.xdb` 数据库的筛选与行数据配置；配套新建独立的 `游戏媒体库.xdb` 作为真实记录的最小验收入口，不改现有动画范围的 `媒体库.xdb`。

### 9.1 文件命名（已确认）

| 角色 | 文件名 | id / 边界 |
| --- | --- | --- |
| 游戏卡片插件 | `媒体库-游戏卡片.xdb.js` | plugin id `agan-game-card` |
| 游戏数据库 | `游戏媒体库.xdb` | 全局 filter：`作品大类 = 游戏 AND 数据来源 = Bangumi` |

命名理由：

- 与《媒体卡片设计规范》第 3 节「游戏卡片」同名，文件名、概念名、字段名共用同一个词，不需要二次映射。
- 与动画侧并列：`媒体库-动画卡片.xdb.js` ↔ `媒体库-游戏卡片.xdb.js`；`媒体库.xdb` ↔ `游戏媒体库.xdb`。
- 不沿用 `gallery-wall`：本 Task 只实现单张卡片，不含筛选、搜索、排序、网格与渐进加载，命名不应承诺画廊能力；游戏画廊另立任务时再单独命名。
- plugin id 带 `agan-` 命名空间，与动画插件的 `agan-anime-media-progress` 一致，并满足 `xdb-plugin-skills` 对扩展点 id「稳定且带插件命名空间」的要求。

### 9.2 与旧游戏卡片墙的关系

`game-gallery-wall.xdb.js` 是旧版画廊级卡片墙（状态 tab + 网格 + `completion_percent` 进度条），使用 `status`、`game_category`、`completion_percent`、`current_playthrough`、`rating` 等英文字段，与本 Task 确定的正式中文字段不一致。本 Task 不修改、不迁移、也不复用它。

该插件注册的 view type `game-gallery-wall` 目前仍被 `媒体库.xdb` 的 `views[1]`（id `98ea34b1-cd8c-47c3-bd62-3ddbf093a85c`，名称「游戏面廊（卡片墙）」）引用；由于 `媒体库.xdb` 的全局 filter 只放行动画，该 view 当前取不到任何游戏记录。它的存废不属于本 Task。

## 10. 修订记录

### 2026-09-30：增加视觉对齐 Requirement（第 1 次修订）

首版实现（`媒体库-游戏卡片.xdb.js` 首稿）只对齐了 `媒体库-动画卡片.xdb.js` 的**注册写法**，没有对齐**视觉系统**：宽度写死 `300px`、标签用中性灰、状态角标无标识色，结果在表格单元格里既窄又平，与动画卡片完全不像。用户据此提出「按动画卡片重做」。

本次修订：

- 第 2 节新增三条 Requirement：视觉与结构对齐动画卡片、宽度随容器自适应（上限 330px）、视觉对齐不含动画卡片的可写操作与进度区。
- 第 3 节补一条 Scope 说明：视觉对齐在范围内，代价是两个插件各持一份同构样式与配色表，一致性由测试固定。
- 第 7 节新增第 7～11 条 Acceptance Criteria（卡片几何、四角徽标、12 组彩色标签、四态状态色、自适应宽度、仍然只读且无进度区）。
- 第 9.2 节所述旧卡片墙 view：用户已裁决删除 `游戏媒体库.xdb` 中的那一个；`媒体库.xdb` 中的同名 view 暂留。

因本次修订改变了 Requirement 与 Acceptance Criteria，按 `WORKFLOW.md` §4.2.2 停止 Implementation，先更新本 Task 与 `Plans/Task 07 - Plan Review.md`，重新取得用户批准后再实现。
