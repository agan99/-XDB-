# Task 04 - Approved Plan

Plan Review 未发现必须停止的 Conflict / Blocker。当前实现能够通过同一插件模块中的共享卡片实例工厂满足“复用 Task 03 卡片”，无需复制卡片逻辑。

## 1. 技术路线

继续扩展现有 `媒体库-动画卡片.xdb.js`，注册读取行数据的第三方 Database View：

```text
view type: agan:anime-gallery
view name: 追番画廊
```

使用：

```js
ctx.registerDatabaseView(...)
```

原因：

- 画廊需要访问完整行集合；
- 需要自行实现正式规定的统计、筛选、搜索、排序和渐进渲染顺序；
- 原生 gallery 无法完整承载本 Task 的交互状态、排序循环、全库固定统计和渐进加载；
- 与 Task 03 位于同一插件模块，可以直接复用同一份卡片渲染和写回实现。

筛选、搜索和排序状态只属于当前画廊实例，不写入媒体笔记，也不持久化为新的业务字段。关闭并重新打开画廊时恢复默认条件。

## 3. Task 03 卡片复用

将现有动画卡片 Renderer 的实例生命周期整理为内部共享工厂，例如：

```text
createAnimeCardInstance()
  → onUpdate(cardProps)
  → onDestroy()
```

现有 `agan:anime-card` Field Renderer 和新画廊都调用该工厂。

画廊为每个已渲染 row 创建卡片容器，并将以下宿主上下文传给同一实例：

- 当前 row；
- `api`；
- `markdown`；
- Obsidian 公共上下文；
- 卡片容器。

画廊不得重新实现：

- 卡片字段读取；
- 标题 fallback；
- 状态映射或写回；
- 收藏与 description 交互；
- Media Progress；
- 卡片内部样式和错误降级。

卡片实例按 row id 管理。移除卡片或销毁画廊时调用对应 `onDestroy()`。

## 5. 画廊纯逻辑核心

在插件中建立无 DOM 依赖、可直接测试的 `animeGallery` 核心对象，负责：

- 从嵌套 `viewData.groups` 收集并按 row id 去重；
- 计算全库固定数量；
- 应用状态和附加筛选；
- 解析搜索词并匹配；
- 执行默认或主动排序；
- 计算排序按钮下一状态；
- 管理渐进加载数量。

处理顺序固定为：

```text
完整动画行集
→ 筛选
→ 搜索
→ 排序
→ 完整结果集
→ 截取当前渐进渲染数量
```

渐进加载只影响最后一步。

## 6. 筛选模型

画廊实例状态：

```text
status: null | watching | planned | completed | paused
favoriteOnly: boolean
unknownTotalOnly: boolean
query: string
sort: null | { field, direction }
```

状态映射复用正式状态值：

```text
watching  → ▶️ 进行中
planned   → ⏳ 待定
completed → ✅ 已完成
paused    → 💭 未来也许
```

行为：

- 点击未选中的状态：设为唯一状态筛选；
- 再次点击当前状态：恢复全部；
- 点击“全部”：只令 `status = null`；
- 不改变收藏、集数未知、搜索或排序；
- 收藏和集数未知分别独立切换；
- 三类筛选之间采用 AND。

`集数未知` 使用现有 Media Progress 的 total 标准化语义：

- `总集数` 缺失、空值或空字符串：未知；
- `0` 是已知值，不属于未知；
- 非法 total 不冒充未知，由卡片现有错误边界处理。

缺失或非法状态不匹配四种状态按钮，但仍计入“全部”。

## 7. 固定全库统计

每次收到最新完整行集时，先计算：

- 全部；
- 在看；
- 想看；
- 已看；
- 暂缓；
- 收藏；
- 集数未知。

统计始终基于应用画廊本地条件之前的完整动画行集。

搜索、当前状态筛选、收藏筛选和集数未知筛选均不得改变按钮数量。卡片写回导致真实数据变化时，统计随最新完整行集更新。

## 8. 搜索

搜索仅使用：

```text
中文名
原名
tags
```

不把 `name`、description 或其它字段加入搜索。

处理方式：

1. 去除输入首尾空格；
2. 按连续空白拆分关键词；
3. 英文字母转为小写；
4. 每个关键词在中文名、原名或任意 tag 中做包含匹配；
5. 单个关键词匹配任一字段即满足；
6. 所有关键词必须同时满足。

空搜索词不限制结果。

## 9. 排序

### 默认排序

没有主动排序时：

```text
状态优先级
→ 开播日期倒序
→ Task 03 卡片标题正序
```

状态优先级：

```text
▶️ 进行中
→ ⏳ 待定
→ 💭 未来也许
→ ✅ 已完成
→ 缺失或非法状态
```

缺失或非法状态作为降级数据排在四种正式状态之后，不修改原数据。

### 主动排序

四个字段及默认方向：

| 按钮 | 默认方向 | 反向 |
|---|---|---|
| 开播日期 | 新 → 旧 | 旧 → 新 |
| 个人评分 | 高 → 低 | 低 → 高 |
| Bangumi评分 | 高 → 低 | 低 → 高 |
| 标题 | 正序 | 倒序 |

单个按钮循环：

```text
未选中
→ 默认方向
→ 反向
→ 取消并恢复默认排序
```

点击其它按钮时，原主动排序取消，新字段从默认方向开始。

共同规则：

- 同时最多一个主动排序；
- 空值始终排在最后；
- 日期只接受有效日期值；
- 评分按有效数值比较，`0` 不是空值；
- 标题复用 `animeCard.resolveTitle()`；
- 主排序值相同时按标题正序；
- 标题相同时保持原始稳定顺序；
- 排序只操作复制后的结果数组，不修改宿主 row 集合。

标题使用适合中英文混排的 locale compare；搜索的英文忽略大小写规则不额外改变标题排序语义。

## 10. 控件和空状态

页面结构：

```text
追番画廊
状态筛选 + 附加筛选
搜索框 + 四个排序按钮
结果区域
```

宽度不足时：

- 筛选控件允许换行；
- 搜索框单独占行；
- 排序按钮整体换至下一行；
- 不把控件压缩到不可操作。

当完整动画行集为空时显示：

```text
暂无动画
当前动画库没有可展示记录
```

不显示新建入口。

当完整行集非空、条件结果为空时显示：

```text
没有找到匹配的动画
调整搜索或筛选条件试试
[清除条件]
```

清除条件执行：

```text
status = null
favoriteOnly = false
unknownTotalOnly = false
query = ""
```

保留主动排序及方向。

## 11. 网格与卡片尺寸

正常宽度使用规则 CSS Grid：

- 卡片槽位固定 `330 × 430px`；
- 自动计算可容纳列数；
- 列宽不拉伸；
- 网格左对齐；
- 最后一行从左向右；
- 统一间距；
- 不使用 masonry；
- 不产生横向滚动。

画廊通过宿主 class/CSS 变量约束共享卡片实例为 `330 × 430px`，不会复制一套卡片 DOM。

现有 table 中的单卡 Field Renderer 保持当前独立尺寸，不因画廊尺寸要求改变其既有展示入口。

极窄容器使用 `ResizeObserver`：

1. 容器宽度小于 330px 时计算 `scale = availableWidth / 330`；
2. 卡片内部仍按 330 × 430px 渲染；
3. 卡片槽位按同比例尺寸占位；
4. 使用左上原点整体缩放；
5. 恢复足够宽度后回到标准尺寸。

`ResizeObserver` 只处理极窄降级，不承担画廊列数计算。

## 12. 渐进加载

批量大小固定为：

```text
24 张
```

流程：

- 完整条件结果先全部完成排序；
- 首次只创建前 24 个卡片实例；
- 网格末尾放置 sentinel；
- `IntersectionObserver` 在 sentinel 接近视口时增加 24；
- 已渲染卡片保留，不实现虚拟列表；
- 达到完整结果数量后停止观察；
- 卡片封面继续使用 Task 03 的 lazy loading。

筛选、搜索或排序由用户改变时：

1. 重新计算完整结果；
2. 将可见数量重置为 24；
3. 销毁不再使用的卡片实例；
4. 从新结果第一批开始；
5. 将结果区域滚动到顶部。

清除条件同样执行该重置。

## 13. 数据更新与滚动保持

区分两类更新：

### 用户改变画廊条件

重置批次并回到结果顶部。

### 宿主因卡片写回而调用 `onUpdate`

保留：

- 当前筛选；
- 搜索词；
- 主动排序；
- 当前已加载数量；
- 当前滚动位置。

使用 row id 做 keyed reconciliation：

- 仍满足条件的卡片复用现有实例；
- 顺序变化时移动原槽位；
- 不再满足条件的卡片立即移除并销毁；
- 结果减少后，用后续匹配卡片补足当前加载数量；
- 新数据只重新计算结果，不调用回顶逻辑。

因此状态或收藏修改可以让卡片移动或离开当前结果，但不会无条件重置整个画廊。正文 current 修改由共享卡片实例自行刷新，不触发第二套画廊进度逻辑。

## 14. 生命周期

画廊 `onUpdate()` 保持同步且可重复：

- 首次创建根 DOM 和控件；
- 后续只更新最新 props、统计和结果；
- 保留画廊实例状态；
- 异步卡片读取仍由共享卡片实例自己的 generation token 管理。

`onDestroy()`：

- 断开 `IntersectionObserver`；
- 断开 `ResizeObserver`；
- 销毁所有卡片实例；
- 清理 DOM 引用和事件监听器；
- 使未完成回调失效。

画廊不注册 vault 级监听器，不创建额外 Source of Truth。
